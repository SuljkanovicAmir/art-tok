# Met search v1.1 migration and cache refill fix (2026-11-06)

## Problem

Instagram Auto-Post stopped publishing after 2026-09-30. Two failures stacked up:

- The Dropbox image cache ran out: all 220 entries were posted or skipped.
- Met retired `/public/collection/v1/search` on 2026-10-01 (HTTP 410), which removed
  the only source that still worked from GitHub Actions.

AIC and Harvard images return 403 to GitHub's runners. The website's Met feed and
search called the same retired endpoint.

## Changes

- `scripts/instagram-poster/lib/art-fetchers.mjs`: new `searchMetIds()` calls
  `/v1.1/search` and walks up to four 500-ID pages. It is used by the random and
  seasonal Met paths.
- `src/services/MetAdapter.ts`: feed and search now request one API page at a time
  with `limit` and `offset`, so the in-memory highlight ID list is gone.
- `scripts/instagram-poster/curator.mjs`: the per-source target and the oil and
  portrait caps now count usable entries only. Counting every entry meant Harvard
  (217 entries) and the oil cap (200) blocked a refill of an empty cache.

`/v1/objects` and `/v1/departments` are still current and did not change.

## v1.1 search behaviour

- Default page size is 100 and the maximum is 500; larger limits are clamped.
- `objectIDs` is missing or `null` past the end of the results, so treat it as empty.
- `q=*` and `isHighlight` still work. CORS allows any origin.

## Refilling the cache

Run `node curator.mjs` locally, then commit `image-cache.json`. As of 2026-11-06,
Harvard images work from a local machine, but AIC images return 403 locally as well
as from CI. New entries have no `aiScore` and stay eligible until scored.
